# 8. 전연령 확대 — 설계 노트 및 완료 기록

> 2026-07-12: "향후 성인 관리로 확대하는 것을 고려해서 설계에 반영" (확장을 막지 않기).
> 2026-07-29: **시장 확대를 위해 실제 확대 진행 — 착수 순서 ①~⑤ 완료.**
> 이 문서는 확장 규칙(계속 지킬 것) + 무엇이 어떻게 구현됐는지를 함께 담는다.

## 확대 배경과 전제 (읽고 넘어갈 것)

사용자 논의에서 "아동 대상이라 법률 문제가 있으니 전연령으로 바꾸면 낫지 않나"라는
동기가 먼저 나왔으나, 검토 결과 **대상군 확대는 법적 의무를 줄이지 않는다**:

- 개인정보보호법 §22-2(만 14세 미만 법정대리인 동의)는 **처리되는 정보의 주체가
  아동이면** 적용된다. 앱을 "전연령"이라 소개해도 아이 기록이 남아 있는 한 의무는 그대로다.
- 건강정보=민감정보(§23) 별도 동의는 연령과 무관하게 적용된다.
- Google Play Families 정책은 **아동이 앱의 사용자**일 때 걸린다. 이 앱의 사용자는
  성인이고 아이는 데이터 주체일 뿐이라 이미 회피돼 있다(docs/09 §5).
- 전연령은 의무의 **합집합**이 된다 — 아동 의무는 유지되고, 성인 대상자를 대신
  기록할 때의 **위임 동의**가 새로 생긴다.

→ 그래서 확대의 근거는 법적 리스크 감소가 아니라 **시장 확대(TAM)** 이며, 이 문서와
구현은 그 전제 위에 서 있다. 법률 검토는 여전히 출시 차단 항목(docs/09 §2-3).

## 구현 결과 (착수 순서 ①~⑤)

| 단계 | 내용 | 위치 |
|---|---|---|
| ① 대상자 유형 | `recipient_type`(child\|adult) + `is_self` 컬럼/필드 | `supabase/schema_recipients.sql`, `src/types` |
| ② 본인 기록 모드 | 등록 폼의 유형 칩 + 본인/다른 성인 선택 | `ChildFormScreen` |
| ③ 동의 분기 | 만 나이 기준 4경로 + `adult_delegated` 동의 유형 | `src/lib/recipient.ts`, `terms.ts` |
| ④ 연령 전제 기능 | 출생 정보·학교 기록·키 성장 곡선을 아이 전용으로 | `recordTypes.ts`, 프로필/기록 폼 |
| ⑤ 명칭 정리 | UI 카피를 "대상자/가족"으로 (테이블·타입명은 유지) | 홈·설정·구독·방침·약관 |

### 동의 분기 — 단일 원천은 `consentPlanFor()`
**라벨(recipient_type)이 아니라 birthDate 기준 만 나이로 판정**한다. 성인으로 표시해도
만 나이가 미성년이면 미성년 기준이 우선한다(테스트로 고정).

| 대상자 | 동의 유형 |
|---|---|
| 만 14세 미만 | `guardian_legal` + `sensitive_health` |
| 만 14세 이상 미성년 | `guardian_legal` + `sensitive_health` (+본인 고지 확인) |
| 성인 본인 | `sensitive_health` |
| 성인 타인 | `adult_delegated` + `sensitive_health` |

> ⚠️ **불변**: 어느 경로든 `sensitive_health`가 포함된다. RLS의
> `has_sensitive_consent()`가 기록 INSERT를 막는 유일한 게이트이므로, 대상자 유형이
> 늘어도 이 게이트를 우회하는 경로를 만들지 않는다(RLS 테스트로 성인 경로도 검증).

## 계속 지킬 규칙

1. **개명은 백로그**: `children`/`child_id`/`Child`는 그대로 둔다. 일괄 개명은 FK·RLS
   정책·Storage 경로까지 번지는 마이그레이션이라 비용 대비 실익이 없다. 의미만
   "관리 대상자"로 읽는다. 새 코드에 아이 전용 가정을 새로 하드코딩하지 않는다.
2. **연령 전제 기능은 스위치로**: 소아 전용 기능을 추가할 때는
   `showsChildFeatures(recipient)` 분기를 반드시 붙인다. 저장된 기록은 유형과 무관하게
   계속 보여야 하므로 **조회 경로에는 필터를 걸지 않는다**(표시 목록에만 적용).
3. **구독 한도 명명**: `maxChildren`은 "등록 대상자 수"로 읽는다 —
   `ENTITLEMENTS` 한 파일만 고치는 구조 유지.
4. **불변 원칙 승계**: 의료행위 금지(진단/용량/내원 판단 금지)는 성인 대상에도 동일.
5. **성인 대상자 권리**: 성인 본인이 기록 중단·삭제를 요청하면 계정 이용자는 지체
   없이 따라야 한다(약관·방침에 명시). 관련 UI(대상자 본인 요청 창구)는 백로그.

## 남은 것 (백로그)

- 성인 특화 기능: 복약 알림 강화, 만성질환 추적, 성인 검진 주기 프리셋 — 베타 후 판단
- 성인 대상자 본인의 권리 행사 창구(앱 외 요청 폼) — 계정 삭제 웹 페이지와 함께 검토
- 명칭 일괄 정리(`children` → `care_recipients`) — view/alias로 점진 전환
