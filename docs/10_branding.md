# 10. 브랜딩 — 앱 이름 변경 기록과 남은 결정

> 2026-07-30: 전연령 확대(docs/08)에 따라 "아이케어"가 대상군과 맞지 않아
> **케어노트(CareNote)** 로 변경. 사용자 결정.

## 확정된 것

| 항목 | 값 |
|---|---|
| 앱 이름 | 케어노트 (영문 CareNote) |
| 태그라인 | 우리 가족 건강 기록, 병원까지 한 번에 |
| slug / URL 스킴 | `carenote` |
| 번들 ID | `app.carenote.mvp` — **여전히 자리표시**(도메인 확정 후 `kr.co.<도메인>.carenote` 권장) |
| 스토어 상품 ID | `carenote.{standard,family}.{monthly,yearly}` |
| 데모 계정 | `demo@carenote.app` (구 `demo@kidcare.app`도 계속 로그인 가능) |
| 기기 저장 키 | `carenote.demo.v1` (구 `kidcare.demo.v1`에서 자동 이관) |

### 이름 변경 시 지킨 것 — 기존 사용자 데이터 보존
앱 이름이 바뀌어도 이미 기기에 쌓인 기록이 사라지면 안 된다. 두 겹으로 처리했다:

1. **저장 키 이관**(`memoryRepo.hydrate`): 새 키가 비어 있으면 구 키
   `kidcare.demo.v1`를 읽어 새 키로 복사한 뒤 그대로 사용한다. 구 키는 롤백
   여지를 위해 지우지 않는다.
2. **구 데모 이메일 인식**(`isDemoEmail`): `demo@kidcare.app`도 데모로 계속
   인정한다. 그러지 않으면 샘플 정리 마이그레이션(`stripSampleData`)이 구 데모
   계정을 일반 계정으로 오인해 샘플을 지워 버린다.

검증: Playwright 영속화 테스트에 마이그레이션 4건 추가(구 키만 있는 기기를
재현 → 자동 로그인·대상자·플랜 보존·새 키 이관 확인). AsyncStorage는 Node에서
동작하지 않으므로 이 검증은 웹(localStorage) 경로에서만 가능하다.

## ⛔ 남은 결정 — 아이콘·상징 이미지

**사용자가 "나중에 결정"으로 보류.** 현재 `assets/`의 아이콘·스플래시는
아이케어 시절 시안(웜톤 배경 + 🧸 곰인형)이 **그대로 남아 있다.**

- 앱 내부에서는 곰인형을 이미 걷어냈다: 로그인 로고는 워드마크만, 홈 빈 상태는 📋.
  (등록 폼의 `🧸 아이` 칩은 브랜드가 아니라 **대상자 유형 라벨**이므로 유지)
- 남은 것은 스토어에 올라가는 자산 3개: `icon.png`, `adaptive-icon.png`,
  `splash-icon.png`. 곰인형 아이콘 + "케어노트" 이름 조합은 전연령 앱으로서
  어긋나 보이므로 **출시 전 교체 필요**(docs/09 §3에 개발 항목으로 등록).
- 방향 후보(당시 제시): ① 기록+하트 ② 가족 실루엣 ③ 그래프 라인 ④ 글자 워드마크.
