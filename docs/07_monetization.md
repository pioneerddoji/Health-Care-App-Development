# 7. 수익화 — 3단계 구독제

## 검토 결과 (2026-07-10)
코드베이스 전수 검색 결과 **기존 수익화 구조 없음** — 결제·구독·프리미엄 게이팅
관련 코드 부재 확인. 이에 아래 3티어 구독제를 설계·구현했다.

## 게이팅 원칙 (신뢰가 곧 리텐션)
1. **핵심 안전 기능은 절대 과금하지 않는다**: 일자별 기록(무제한), 모든 그래프,
   성장 차트, PDF 레포트 생성·직접 공유, 접종/검진 알림, 동의 관리, 데이터 삭제.
2. **이미 기록된 데이터는 다운그레이드해도 잠기거나 삭제되지 않는다**
   (읽기는 항상 가능 — 한도는 "새로 추가"에만 적용).
3. 과금 대상은 **규모와 편의**: 다자녀 수, 공동 보호자 수, 사진 장수,
   대시보드 기간, 공유 링크 옵션.

## 가격 전략 — 얼리버드 + 연간 플랜 (2026-07-12 사용자 결정, 최종)

1차 출시는 **무료 플랜만 개방**하고, 무료 출시 기간 가입자(얼리버드)에게 유료
플랜을 **월 ₩1,000 할인**해 준다. 연간 결제는 **월 정가 ×10 ("2개월 무료" ≈ 17% 할인)**.

| | 정가 (과금 시작 후 신규) | 얼리버드 (무료 기간 가입자) |
|---|---|---|
| 스탠다드 월간 | 월 ₩2,900 | 월 ₩1,900 |
| 스탠다드 연간 | 연 ₩29,000 | 연 ₩19,000 (월 ₩1,583 꼴) |
| 패밀리 월간 | 월 ₩4,900 | 월 ₩3,900 |
| 패밀리 연간 | 연 ₩49,000 | 연 ₩39,000 (월 ₩3,250 꼴) |

- **가격의 단일 원천**: `src/constants/subscription.ts`의 `PRICING`(숫자) —
  표기 라벨·페이월·테스트가 전부 여기서 파생된다. 가격 조정 = 이 객체만 수정.
- **연간 설계 원리**: ×10 규칙(2개월 무료)은 소통이 쉽고("연간 결제하면 2개월
  공짜"), 얼리버드 할인과 곱으로 깔끔하게 중첩된다(연 ₩10,000 할인). 연간의
  월 환산가를 작게 병기해 가격 매력을 보이게 함.
- 페이월 표기: 월간/연간 토글 + 정가 취소선 + 우측 할인가 + 상단 얼리버드 배너.
  숨김(hidden) 모드에서도 표기해 무료 기간의 가입 유인으로 쓴다.
- **자격 판정**: "과금 기능 출시일 이전 가입 계정" — 서버의 `auth.users.created_at`으로
  판정 가능(추가 스키마 불필요). 구현은 Play 구독(티어당 구독 1개 + 월간/연간
  base plan 2개)의 개발자 지정 오퍼 + RevenueCat Offering 2종(default/earlybird).
- 스토어 상품 4개: `carenote.{standard,family}.{monthly,yearly}` (billing.ts PRODUCT_IDS
  = 웹훅 매핑과 테스트로 일관성 검증).
- ⚠️ **법적 필수 조건(표시광고법)**: 취소선 정가는 실제 판매(될) 가격이어야 한다.
  과금 시작 후 얼리버드가 아닌 신규 가입자에게는 **반드시 정가를 부과**할 것.
- 남은 결정: 할인 **유지 기간** — 권장: 구독을 유지하는 한 계속(락인 효과 극대화).
  앱 문구는 기간을 확정하지 않았으므로 결정 후 문구 보강.

## 구현 구조

| 계층 | 내용 |
|---|---|
| 정의 | `src/constants/subscription.ts` — 티어 메타/한도/페이월 행. **한 파일만 고치면 한도 조정 끝** |
| DB | `supabase/schema_subscriptions.sql` — `subscriptions` 테이블(쓰기는 service_role만=스토어 웹훅), `my_tier()`(만료 시 free 강등) |
| **서버 강제** | 아이 수: `guardian_child` INSERT 트리거 / 공동 보호자 수: `invite_guardian` RPC. → 클라이언트 우회 불가 |
| 클라이언트 게이팅 | 사진 장수·대시보드/레포트 기간·공유 링크(옵션/개수) — 우회 피해가 본인 한정이라 UI 게이팅으로 충분 |
| UI | `PaywallScreen`(티어 비교+전환), 설정 플랜 카드, 각 화면 🔒 칩 → 페이월 유도 |
| 데모 | `demo@carenote.app` 로그인은 standard로 게이팅 체험, 일반 가입/로그인은 free 시작 |

> 참고: **데이터 축적(기록 저장)은 전 티어 무제한**이다. 티어가 가르는 것은
> 대시보드의 "조회 기간"뿐. "무제한 조회 플랜"은 30일 초과 구간에서 일 단위
> 그래프의 가독성이 무너지므로, 월별 집계 뷰(월 평균/최고 체온 등)를 먼저
> 만든 뒤 패밀리에 포함하거나 상위 티어로 내는 것을 권장 — 결정은 베타
> 피드백 이후로 보류(백로그).

## 결제 연동 구조 (2026-07-12 준비 완료 — SDK 계약만 남음)

구독의 진실 원천은 `subscriptions` 테이블이고 클라이언트는 읽기만 한다.
결제 연동에 필요한 구조는 모두 저장소에 준비돼 있다:

| 구성 요소 | 위치 | 상태 |
|---|---|---|
| 결제 추상화 (상품 ID·구매·복원) | `src/services/billing.ts` | ✅ 교체 지점 2개 함수에 RevenueCat 코드 가이드 주석 |
| 페이월 모드 플래그 | `resolvePaywallMode()` — env `EXPO_PUBLIC_PAYWALL_MODE` | ✅ `demo`(mock 기본) / `hidden`(supabase 기본) / `live` |
| 웹훅 Edge Function | `supabase/functions/billing-webhook` | ✅ 배포만 하면 됨 (`RC_WEBHOOK_TOKEN` 시크릿 필요) |
| 페이월 UI 3모드 분기 | `PaywallScreen` | ✅ live 모드에 iOS 필수 "구매 복원" 버튼 포함 |
| 일관성 테스트 | `test:gating` 19건 | ✅ 상품 ID↔티어 매핑, 안전 기본값 검증 |

**안전 기본값**: env 미지정 시 실서버(supabase) 빌드는 자동으로 `hidden` —
결제 수단 없이 구매 UI를 노출하면 Play 리젝 사유이므로, 결제 연동을 명시적으로
켜기(`live`) 전까지 전환 버튼이 보이지 않는다. 1차 무료 출시는 그대로 빌드하면 된다.

### 결제 수단 선택 검토 (2026-07-12, 사용자와 논의)

**결론: 앱 내 구독은 한국·글로벌 모두 스토어 인앱결제 + RevenueCat** (준비된 구조 그대로).
- 디지털 구독은 스토어 정책상 인앱결제 의무. 한국 인앱결제강제금지법의 제3자
  결제는 수수료 4%p 인하 vs PG 4~6% + 운영 부담으로 실익 없음(실효성 논란 지속).
- 구독 수수료 15%. 2026-03 구글 발표: 전체 수수료 최대 30→20% 인하(콘텐츠/서비스
  15%), 한국 12월 시행 예정 — **계약 시점에 요율 재확인**.
- RevenueCat: 월 추적 매출 $2.5K까지 무료, 이후 1% → ₩2,900 기준 구독자 약
  1,100명까지 무료.

**웹 결제 채널(2단계 확장 시)**:
- 한국: 토스페이먼츠(정기결제 빌링) 또는 포트원(멀티 PG). 통신판매업 신고·부가세
  직접 신고·해지/환불 UI 의무.
- 글로벌: **Stripe는 한국 사업자 미지원**(2026 현재) → **Paddle**(Merchant of
  Record, 한국 셀러 지원, 각국 판매세 대행, 수수료 ~5%+건당 소액)이 현실적 대안.
- 아키텍처는 이미 대응됨: subscriptions 테이블로 수렴하는 웹훅 소스만 추가
  (토스/Paddle 웹훅 Edge Function을 billing-webhook과 나란히).

**단계**: v1.0 한국 무료(hidden) → v1.1 RevenueCat 과금 → 글로벌은 Play 국가 추가
→ (선택) 웹 채널(연간 플랜 등).

### 실연동 절차 (2026-07-17 코드 측 완료 — 남은 것은 전부 계정 작업)

**코드는 끝났다**: react-native-purchases 설치·`billing.ts` 실구현
(configure/logIn/구매/복원, Google `상품ID:basePlanId` 형식 대응, 사용자 취소 처리),
AppContext가 로그인/복원 시 `initBilling(uid)`·로그아웃 시 세션 정리를 호출한다.
SDK는 live 모드 + env 키가 있을 때만 지연 로드되므로 demo/hidden 빌드와
Expo Go/웹은 영향이 없다.

남은 계정 작업 체크리스트:
1. [ ] Play Console/App Store Connect에 구독 상품 등록 — ID는 `PRODUCT_IDS` 4개
   (`carenote.{standard,family}.{monthly,yearly}`; Play는 구독 2개 × base plan
   monthly/yearly 구성 권장 — 앱은 `:basePlanId` 형식도 매칭한다).
2. [ ] RevenueCat 프로젝트 생성 → 스토어 연결 → Entitlement/Offering 구성.
   얼리버드는 Offering 2종(default/earlybird) + **Targeting(가입일 기준)**으로
   서버에서 노출을 제어 — 앱은 current offering만 읽으므로 앱 업데이트 불필요.
3. [ ] 공개 SDK 키를 EAS Secrets로: `EXPO_PUBLIC_RC_API_KEY_ANDROID`(/`_IOS`).
4. [ ] 웹훅 배포: `supabase secrets set RC_WEBHOOK_TOKEN=<랜덤>` →
   `supabase functions deploy billing-webhook --no-verify-jwt` →
   RevenueCat 대시보드에 URL+Authorization 헤더 등록.
5. [ ] 운영 빌드 env에 `EXPO_PUBLIC_PAYWALL_MODE=live` 추가 후
   **development/production build**(Expo Go 불가).
   ⚠️ EXPO_PUBLIC env 변경은 Metro 캐시에 안 잡힘 — 빌드 시 `--clear` 필요.
6. [ ] 심사 주의: 구독 안내에 가격·기간·자동갱신 고지 필수. 복원 버튼은 이미 있음.
7. [ ] 샌드박스 결제 테스트: 구매 → 웹훅 수신 → subscriptions 갱신 → 앱 loadAll
   반영까지 한 사이클 확인.
