# MVP 베타 진입 결정 — canonical RC + 3개 벤치마크 종합

> 결정 기준일: 2026-08-24 KST  
> 범위: 코드/정적 CI release candidate, 공개 벤치마크 3건, 5~10가족·21일 비공개 무료 베타  
> 금지 범위: 이 결정 작업에서는 배포, 광고, 고객 접촉, 결제 생성, 운영 secret 변경을 수행하지 않았다.

## 1. 결론

**Conditional Go**다.

- **지금 Go:** canonical RC `c171f0459e584a6e1324738fd9a60e6b1587b6d4`를 베타 기준선으로 고정하고, 합성/샘플 데이터 staging 드릴과 아래 3개 제한 실험 구현을 준비한다.
- **실가족 21일 베타는 조건부:** 운영 Supabase/Edge, 두 실기기 권한·회수, preview build, 개인정보·동의 문구를 검증하고 캡틴이 명시 승인한 뒤에만 시작한다.
- **현재 No-Go:** 실가족 건강정보 입력, 공개 모집·광고, 스토어 제출, 실제 결제, OAuth/SMS/RevenueCat 실연동. 코드/정적 CI 통과는 native·hosted backend·법률·운영 준비 통과가 아니다.

기능 수를 더 늘리는 대신 `짧은 기록 → 두 번째 보호자의 확인 → 검토된 진료 브리핑`을 하나의 안전한 루프로 검증한다. 즉시 반영 후보는 정확히 3개이며 나머지는 beta-after backlog로 보낸다.

## 4. 즉시 반영할 제한 실험 3개

작업량은 canonical RC 위에서 구현·테스트·두 플랫폼 실기기 스모크까지 포함한 1인 기준 추정이다. 5~10가족은 추론 통계에 너무 작으므로 절대 가족 수와 안전 guardrail을 함께 본다.

### 실험 1 — 첫 기록 직후 공동 보호자 activation

- **변경:** 무료 베타에서 대상자당 첫 공동 보호자 1명을 허용한다. 첫 기록 저장 성공 뒤 한 번만 `함께 확인할 보호자 초대`를 비차단 CTA로 노출하고 `나중에`를 둔다. 발신자에게 `전송 / 수락 / 타 보호자 첫 확인`을 구분해 보여 준다.
- **측정 이벤트:** `circle_created`, `subject_created`, `record_created`, `invite_created`, `invite_accepted`, `record_acknowledged`, `invite_revoked`. 이벤트는 분석 선택 동의가 true일 때만 pseudonymous·allowlist payload로 적재한다.
- **성공:** 참여 가족의 70% 이상(5가족이면 4가족, 10가족이면 7가족)이 첫 기록 후 7일 안에 초대 수락과 다른 보호자의 첫 확인까지 완료하고, 5가족 모두 역할 범위를 설명할 수 있다.
- **중단/원복:** viewer 쓰기·자기 승격·미수락 수신자의 건강정보 노출이 1건이라도 발생하면 즉시 전체 베타를 중단한다. 오수신자/오초대 신고가 1건이라도 있으면 해당 초대 경로를 중단하고 원인 확인 전 재개하지 않는다. activation이 50% 미만이면 홈 CTA 위치/문구만 재검토하며 기능 확장은 하지 않는다.
- **예상 작업량:** 2~3인일. entitlement/RPC·RLS mirror, 완료 CTA·상태 UI, 이벤트 연결, 회귀/실기기 드릴 포함.
- **되돌리기:** free entitlement를 0으로 되돌리고 CTA feature flag를 끈다. 기존 승인된 관계를 자동 잠그지 않고 owner가 내보내기/회수 선택을 하게 한다.

### 실험 2 — `오늘의 돌봄 상태` 3칸 handoff

- **변경:** 홈에 `마지막 관찰 / 다음 예정 / 담당·확인` 세 칸과 `확인했어요`만 제공한다. 자유 채팅, 감정 피드, 위치 공유, 새 범용 캘린더는 만들지 않는다.
- **측정 이벤트:** `record_created`, `record_acknowledged`, `task_assigned`, `task_completed`, `trust_issue_reported`. 주간 지표 WCC는 KST 월요일 기준으로 서로 다른 사용자 2명, 기록 3건 이상, 확인 또는 task 완료 1건을 만족한 circle이다.
- **성공:** 3주 중 최소 2주에 참여 circle의 60% 이상(5가족이면 3가족, 10가족이면 6가족)이 WCC를 충족하고, owner 외 구성원의 확인/기여가 적어도 1회 있다.
- **중단/원복:** 중복 기록률이 baseline 대비 5%p 이상 악화, viewer 쓰기 1건, 건강 원문이 이벤트/로그에 노출 1건, 또는 상태와 실제 기록의 불일치 1건이면 즉시 해당 surface를 끈다. 2주 연속 40% 미만이면 beta-after로 되돌린다.
- **예상 작업량:** 1.5~2.5인일. 기존 handoff 계약을 실제 Home/Repo에 연결하고 offline/retry/role 테스트를 추가한다.
- **되돌리기:** 홈 card feature flag만 끄며 원본 기록·권한 데이터는 바꾸지 않는다.

### 실험 3 — 검토형 60초 진료 브리핑 진입점

- **변경:** 진료일 또는 충분한 최근 기록이 있는 경우 홈에 `진료 브리핑 초안` 진입점만 추가한다. 기간·요약·보호자 질문을 사용자가 검토/편집한 뒤에만 PDF/만료 링크를 만든다. 진단 추정·약 용량·수진 필요성 판단은 영구 금지다.
- **측정 이벤트:** `episode_started`, `briefing_generated`, `briefing_edited`, `briefing_exported`, `briefing_used_reported`, `episode_completed/cancelled`. 증상·약 이름·질문·PDF 본문은 이벤트에 넣지 않는다.
- **성공:** 실제 진료 episode가 있는 가족의 60% 이상이 브리핑을 생성하고, 생성 가족의 50% 이상이 검토 후 PDF를 내보내거나 진료에 사용했다고 응답한다. 기존 기록이 있는 경우 생성 p50은 60초 이하다.
- **중단/원복:** 미검토 자동 공유, 의료 판단 문구, 회수/만료 후 신규 접근, 원문 건강정보 analytics 유출이 1건이라도 있으면 즉시 중단한다. 생성 p90이 5분 초과하거나 생성 후 이탈이 30% 초과면 홈 진입점을 끄고 흐름을 축소한다.
- **예상 작업량:** 1~2인일. Home entry, eligibility rule, 검토 상태, privacy-safe event 연결, 실제 PDF/share 드릴 포함.
- **되돌리기:** proactive entry만 끄고 기존 사용자가 명시적으로 여는 Report 화면은 유지한다.

## 5. beta-after backlog

다음은 21일 베타 admission을 지연시키지 않는다.

- 복약 체크인/리필/약물 DB/상호작용: 반복 가치 후보지만 알림·중복·의료안전 범위가 별도다.
- AI 상관관계·진단 추정·약 용량·수진 판단: 앞의 하나는 충분한 데이터와 설명 가능성 전까지 보류, 뒤의 세 가지는 영구 금지다.
- 공개 커뮤니티·감정 피드·후원·광고·위치 추적·범용 채팅/캘린더.
- 병원 포털 대량 연동, OCR 문서 수집, 외부 약 DB.
- RevenueCat·실결제·유료 고급 리포트, 가격 A/B 테스트.
- 성장 백분위, 다국어, 소유권 이전, 사진 서명 URL 장기 재발급 등 기존 백로그.
- 미성년→성인 자동 권한 회수는 공개 출시 전 P0 정책이지만, 이번 21일 아동 보호자 베타에서 연령 경계 대상자를 모집하지 않고 별도 법률/설계 카드로 분리한다.

## 6. staging → 실기기 → 5~10가족 21일 실행안

### Phase A — admission 준비(D-7~D-1)

1. canonical SHA와 build/version을 고정하고 rollback owner를 지정한다.
2. 캡틴 승인 후 staging Supabase를 만들고 migrations/RLS/Storage를 적용한다. 실데이터 없이 두 테스트 계정으로 `verify:supabase`를 전부 통과시킨다.
3. `share-report`와 `delete-account` Edge 경로를 배포하고 샘플 PDF/계정으로 링크 열람→회수→만료, 내보내기→삭제→DB/Storage 차단을 확인한다.
4. 개인정보·민감정보·선택 analytics 동의 문구, 보존기간, 사고 연락 경로를 고정한다. 건강 원문 없는 운영 지표만 허용한다.
5. Android/iOS 각 1대 이상에서 가입→동의→대상 등록→기록→초대(두 기기)→확인→브리핑/PDF/share→회수→동의 철회→삭제를 수행한다. 권한 거부, 오프라인, 앱 재개, TalkBack/VoiceOver도 포함한다.
6. preview artifact의 SHA/build 정보를 기록한다. 실패가 하나라도 남으면 실가족 모집을 시작하지 않는다.

### Phase B — 21일 비공개 무료 베타

- **표본:** 5~10가족, 가족별 owner 1명 + 가능하면 공동 보호자 1명. 중간에 목표 표본을 늘려 성공처럼 보이게 하지 않는다.
- **Day 0:** 동의, 권한 설명 확인, analytics 선택 동의, 첫 기록. 운영자는 건강 원문을 보지 않는다.
- **Day 1~7:** 실험 1 activation과 실험 2 첫 WCC를 관찰한다. 24시간 미수락 안내에는 건강정보를 넣지 않는다.
- **Day 8~14:** 테스트 구성원/샘플 링크 회수 드릴, 이전 세션·링크 재접근 차단 확인. 두 번째 WCC를 관찰한다.
- **Day 15~21:** 진료 episode가 있는 가족만 실험 3을 수행한다. 진료가 없는 가족에게 가짜 의료 상황을 만들게 하지 않는다. 세 번째 WCC와 오류 복구를 확인한다.
- **종료:** owner가 계속 사용, 내보내기 후 삭제, 즉시 중단 중 하나를 선택한다. 분석 이벤트는 최대 30일 후 삭제하고 집계만 보존한다.

### 전체 베타 성공 기준

- 보안 P0 사건 0건: 무권한 읽기/쓰기, 오수신자 건강정보 노출, 회수 후 신규 접근, 원문 analytics 유출.
- 5가족이면 최소 4, 10가족이면 최소 7가족이 첫 기록을 완료한다.
- 실험별 성공 기준을 적어도 2개 충족하고, 나머지 1개는 안전 guardrail을 위반하지 않은 채 명확한 개선 가설을 남긴다.
- 참여 가족 전원이 내보내기/삭제/회수 경로를 찾을 수 있다.

### 전체 베타 즉시 중단 기준

- 보안·개인정보 P0 1건, 의료 판단 오인 1건, 삭제/회수 실패 1건, 또는 건강 원문이 지원 티켓/분석 로그에 복사된 1건.
- 반복 crash/데이터 손실이 동일 핵심 흐름에서 2가족 이상 발생.
- 법률/정책 검토에서 현 동의·처리 구조로 실가족 데이터를 받을 수 없다는 판단.

중단 시 신규 로그인/초대를 막고, 링크·토큰 회수→영향 이벤트 보존→owner 통지 초안→내보내기/삭제 지원 순서로 처리한다. 원문 건강정보를 사고 티켓에 복사하지 않는다.

## 7. 임시 브랜드·가격 가설과 무료 베타 범위

### 브랜드

- 저장소/개발 코드명: `CareNote`/`아이케어` 유지.
- 사용자 검증용 가칭 1순위: **`돌봄한장`** — “가족이 함께 기록하고 진료 전에 한 장으로 정리” 가설을 검증한다.
- 상표·도메인·Play/App Store 중복 확인 전에는 외부 확정명으로 쓰지 않는다. 21일 베타 종료 후 이름 이해도·신뢰도만 질문한다.

### 가격

- 후속 가설: Standard 월 ₩2,900, Family 월 ₩4,900. 이는 판매가가 아니라 조사할 가설이다.
- 얼리버드 ₩1,900/₩3,900과 취소선 정가는 실제 정가 판매·유지기간이 확정되기 전 노출하지 않는다.
- 21일 베타에서는 `offer_viewed`, `paid_intent_clicked`, 결제 버튼, 카드/스토어 결제를 모두 끈다. 가격은 성공 기준에 포함하지 않는다.

### 무료 베타 포함/제외

- **포함:** 대상 1명, 공동 보호자 1명, 기록·그래프·오늘 handoff·기본 알림·7일 PDF·24시간 링크 1개·동의/내보내기/삭제·3개 실험.
- **제외:** 추가 대상/보호자, 결제·구독 전환, 광고/후원, AI 의료 판단, 외부 병원/약 DB, 공개 링크/검색, 무제한 문서 저장.
- 다운그레이드나 베타 종료로 기존 건강 데이터가 잠기지 않는다. 신규 추가 한도만 막고 먼저 내보내기/삭제를 제공한다.

## 8. 캡틴 승인 게이트

아래는 코드로 대신할 수 없으며, 별도 승인 전 실행하지 않는다.

| 운영 항목 | 이번 베타의 제안 | 캡틴 승인 내용 | 승인 전 상태 |
|---|---|---|---|
| Supabase | staging 서울 리전, 프로젝트 소유·요금·secret 보관, migration/RLS/Storage 적용 | 프로젝트 생성/비용/접근자와 secret 주입 승인 | **차단** |
| Edge | `share-report`, `delete-account` staging 배포와 샘플 수신자 드릴 | deploy, 로그/retention, rollback 승인 | **차단** |
| OAuth/SMS | 이번 베타는 email-only. SMS 스텁을 사용자에게 노출하지 않고 OAuth는 보류 | email-only 예외와 인증 문구 승인 | **차단** |
| Build/signing | 내부 preview build만. 스토어 업로드·production signing은 금지 | EAS 계정/secret 사용, 테스트 기기 설치 승인 | **차단** |
| 법률/개인정보 | 보호자·민감정보·선택 analytics 문구와 보존/삭제 절차 검토 | 실가족 데이터 수집 가능 여부 승인 | **차단** |
| 고객 접촉 | 동의된 5~10가족 비공개 초대, 보상·지원 채널·연락문 승인 | 대상/문구/일정/보상/incident 연락 책임자 승인 | **차단** |
| 결제 | 생성하지 않음; paywall/purchase CTA hidden | 별도 승인 불필요. 향후 실결제는 새 gate | **금지 유지** |
| 공개 배포/광고 | 수행하지 않음 | 별도 프로젝트 결정 필요 | **금지 유지** |

승인 기록에는 승인자, KST 시각, 범위, 만료/철회 조건을 남긴다. 하나의 포괄 승인으로 production·결제·광고까지 확대하지 않는다.

## 9. 최종 의사결정 규칙

- **Go:** Phase A의 hosted backend/Edge/두 실기기/preview build/개인정보 gate가 전부 PASS이고 캡틴의 고객 접촉 승인이 있을 때, 5~10가족 21일 무료 베타만 시작한다.
- **Conditional Go(현재):** canonical RC와 실험 설계는 채택하되 Phase A가 끝날 때까지 합성·샘플 데이터만 사용한다.
- **No-Go:** P0 안전 실패, 법률 차단, 회수·삭제 실패, 운영 책임자/rollback 부재 중 하나라도 있으면 실가족 베타를 시작하지 않는다.

이 결정은 “출시 준비 완료”가 아니라, 작은 베타에서 무엇을 증명하고 어떤 조건에서 멈출지를 고정한 admission contract다.
